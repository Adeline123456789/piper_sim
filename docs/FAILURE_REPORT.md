# 失败结论与交接

本次目标是用真实视频/轨迹和系统辨识修正仿真，近一比一复现插入失败掉落，再收集可信的仿真数据。**该目标未达成，判定失败。** 用户要求结束辨识并完整归档。

## 已有成果及边界

- 双Piper、桌面/显示器/中心支架、两种插座与插头、三相机场景及原生Control同步代码已有实现。外观接近不代表物理一致。
- 灰座170×60×33mm，白排212×76×30mm；黄色插头40.9g为用户实测。夹爪内侧为带纹路的硬质橡胶。未称量的惯量和COM不能称实测。
- 实际有完整失败采集及模型内成功采集。模型内成功依赖仿真物体位姿的专家控制，不是已部署的视觉策略。
- 接入官方`mujoco.sysid`，完成一组空载优化；RAX只参考了冻结产物和验证思路，没有完成RAX基准集成。

## 尚未解决的问题

1. 实物与仿真的夹持位置、相对滑动、翻转方向及落点不一致。
2. 同一候选改变积分步长后可能从掉落变为持续夹持，不能把单次好看视频当物理复现。
3. 相机/基座/孔位映射、实际夹爪开口和受力模型没有完成独立标定。
4. 未完成跨轨迹和新布局验证；不能承诺sim-to-real直接部署。

## 撤回力矩解释

没有六维力/力矩传感器，也没有经过独立校准的接触力记录。CAN/SDK中effort字段可能是驱动器内部反馈/估计，本项目没有验证其实际物理来源和量纲。旧文件的Nm名称来自SDK描述与缩放，不足以把数字称为实测力矩。保留原始字段便于追溯，**撤回“用实测力矩完成受力辨识”的说法**。模拟器输出的actuator_force/contact force也不是实物测量。

最近空载试验留出开度RMSE约0.400→0.399mm，几乎没改善；effort代理数值误差下降不构成受力辨识成功。结果触及参数边界并达到迭代预算，未采纳为带载默认。

## 数据标签

真实失败标签保留。历史仿真success=true仅指生成时该模型内任务条件成立，不能扩展成“真实成功”或“仿真环境已标定”。旧候选仍归档供调查，不再作为已验证部署参数推荐。没有为凑成功数而修改标签。
